Bottom line

You already own every layer of the workflow except one — but each layer is implemented two to five times, in two languages, and no repo is mature or central in more than two of the seven dimensions. The universal hole is graph / relationship structure (best score anywhere: 2/3, research-plugin's wikilink backlinks; MRP's Kuzu graph pipeline never reaches the live app). Insight extraction is prompt-encoded everywhere with no deterministic engine.

Recommended spine: research-plugin (the only live, dual-host Codex + Claude Code plugin, 187 entries, written to yesterday) as the knowledge substrate and agent surface, fed by Omniparse (already vendored there) and stratagem's SEC/scrape tools, with three donor modules bolted on: local-smartz/runners/ for a headless local/cloud provider router, market-research-platform/backend/app/storage/vector_store.py for sqlite-vec embeddings, and stratagem/tools/reports.py + presentation.py (plus MRP's email/notes/outline generators) as the one renderer set. Build the graph layer once, on top of research-plugin's SQLite. Retire market-intel; park market-research's web UI.

Composition layers

Donor modules and the net-new work recommended for each workflow layer.

  1. 1 · Collect

    Donors: Omniparse (files) · stratagem sec_edgar.py + sec_client.py · local-smartz tools/web.py (scrape + ddgs search) · MRP OCR path for image PDFs

    New: a scheduled feed/watch collector (RSS + saved queries) as a LaunchAgent, writing straight into the research-plugin KB. Host mode keeps delegating search to WebSearch/WebFetch.

  2. 2 · Assess

    Donors: research-plugin's tiering + verifier + depth classifier + staleness, unchanged

    New: Merge MRP's domain list into domain-scores-seed.json. Add MRP's 5-dim brief-quality rubric and stratagem's report_critic rubric as the assessment of outputs.

  3. 3 · Structure

    Donors: research-plugin's SQLite (backlinks, MOCs) · MRP vector_store.py (sqlite-vec + FTS5, RRF) · MRP embeddings/ (Ollama/MLX/ST)

    New: entity + relation tables in the same SQLite; extraction prompt with a JSON contract (run by host or by the runner layer); cross-entry entity resolution; graph export → JSON + a static HTML view. Kuzu stays optional. This is the only layer with no working donor.

  4. 4 · Insight

    Donors: stratagem source_verifier.md (VERIFIED/SUPPORTED/UNSOURCED/CONTRADICTED/STALE) · financial_analyst.md trend-over-snapshot · local-smartz analyzer.md + bounded fact-check loop · research-plugin atoms

    New: a deterministic pass over verified atoms — same metric, different values across entries → contradiction candidate; entity with sources but no claims → gap; atom series by date → trend table. Prompts then narrate, not discover.

  5. 5 · Synthesize

    Donors: stratagem tools/reports.py + presentation.py (md/pptx/docx/html) + MRP email_/notes_/outline_generator.py → one renderers package · Registers from research-plugin's 5 templates + output-contracts.md and stratagem's executive_synthesizer.md + output_formats.md

    New: one synthesize --register {long,short,highlights,deck} entry that picks template + renderer; deck = outline + slide text (markdown) and optional .pptx via stratagem's builder.

  6. 6 · Models

    Donors: local-smartz runners/ (Ollama/Anthropic/OpenAI/Groq, fail-closed local-only, per-role pins, retry, cost) · MRP MLXProvider grafted in as a fifth runner

    New: Host mode = no runner, host does the calls (research-plugin policy preserved).

  7. 7 · Agent surface

    Donors: research-plugin's dual-host packaging (commands, skill, hook, both plugin.jsons)

    New: Add an MCP server (stratagem's server.py pattern) so Codex, Claude Code, and local-smartz's MCP client all reach the same tools. Turn local-smartz's MCP/plugin tools on by default once this exists.
